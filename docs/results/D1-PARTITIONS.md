## Split rule

By recording session (owner audio), by generation batch (TTS sets —
a whole set, including its train/val TSVs, sits in one partition so
no utterance family crosses partitions), and by case chronological
(Oyez/SCOTUS). Never by sentence within a session or case.
`data/oyez-pilot` is the same case as `data/oyez-bulk/10-218_2011`
(byte-identical `session.tsv`); both paths sit in TRAIN under
`case:10-218_2011`. `data/session` follows its case `24-889_2025` into DEV.
`bulk_tts_1k_trimmed` is a silence-trimmed derivative of `bulk_tts_1k`;
both sit in TRAIN so derivatives never straddle a split.

## Design decisions beyond the bead text (explicit)

1. TTS sets split by whole generation batch, not per file: the bead
   names session/case units; a TTS batch is the session analogue, and
   whole-set assignment keeps trimmed derivatives (`bulk_tts_1k_trimmed`)
   from leaking across partitions.
2. Manifest entries carry a logical `root` (`repo` or `better-voice`)
   instead of absolute paths; the test resolves better-voice via
   `$HEARSAY_BETTER_VOICE_ROOT`, `$BETTER_VOICE_ROOT`, or the
   `../better-voice` sibling checkout, and prints SKIP (not a silent
   pass) for external existence/checksum checks when unresolved.
3. LOCKBOX is seeded with the two latest chronological SCOTUS cases
   already in the repo; owner LOCKBOX sessions follow the same seal
   procedure when recorded.
